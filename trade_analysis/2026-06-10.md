# Trade Analysis — 2026-06-10: Would the fib≥1.0 filter have helped?

**Question:** Would gating entries on fib extension ≥ 1.0x have changed today's results?

**Headline answer:** Naively yes — it would have blocked **all 32 positions** (every
trade today graded fib < 1.0x), turning the day's **−$488** (UTC ledger day) into $0.
But that's because **the fib metric is broken, not because the filter is good**: as
implemented it can never exceed 1.0, so a ≥1.0 gate is equivalent to turning the bot off.

## The bug

`app/strategy/grader.py` `_check_fib_displacement` (line ~464):

```python
b2 = disp.displacement_bar
manip_range = b2.high - b2.low  # sweep bar range as proxy  <-- WRONG BAR
extension = disp.body_size / manip_range
```

`body_size` = |close − open| of the displacement bar; `manip_range` = high − low of
**the same displacement bar**. Body ≤ range always, so extension ∈ [0, 1.0]. The
docstring says the manipulation leg should be the **sweep bar**, but the code uses the
displacement bar "as approximation". The metric currently measures candle
body-to-range ratio (a momentum proxy), not reversal-vs-manipulation extension.

**Ledger evidence (all days with grade data):**

|---|---|---|

| 06-04 | 5 | 0 |

94 entries, 4 ever at fib ≥ 1.0 — all exactly **1.00** (full-marubozu displacement
bars). Max observed = 1.00, confirming the cap.

This also reframes the 06-08 finding ("fib<1.0 on A− is the morning loss driver"):
since ~96% of all trades are fib<1.0, the metric has almost no discriminating power.

## Recommendations (priority order)

1. **Fix the fib computation before using it as a gate.** Measure the displacement
   (reversal) body against the **sweep/manipulation leg** — e.g. sweep-bar range, or
   the distance from sweep extreme back to the displacement origin — per the
   docstring's intent. Until then, any fib threshold ≥ 1.0 is just an off switch.
2. **Re-run the 06-08 "fib filter" backtest after the fix** to see whether a real
   extension multiple separates winners from losers.
3. **Revisit `grader_min_grade: "F"`** — today the bot traded exclusively D/F setups
   at a 22% win rate. The grade scorecard itself (which weights the broken fib 0–30
   points) also needs re-validation after the fix.
